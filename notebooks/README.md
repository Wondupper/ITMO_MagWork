# `notebooks/` — ноутбуки для фигур работы

Четыре ноутбука, из которых берутся все иллюстрации магистерской работы.

Они **намеренно тонкие**: импорт из [`src/viz/`](../src/viz/README.md), вызов,
сохранение. Никакой логики, никаких расчётов, никаких «быстро посчитаю прямо
здесь». Причина не в стиле, а в измеримости результата: если ноутбук пересчитает
метрику по-своему, число на графике и число в таблице работы могут разойтись —
и защищать будет нечего.

---

## Содержимое

| Ноутбук | О чём | Читает | Модуль |
|---|---|---|---|
| `01_audio_features.ipynb` | Что вообще видит модель: осциллограмма, спектрограмма, карта признаков — для подлинной и синтетической записи | аудио из `data/raw/` + `.npy` из кэша | `viz/audio.py` |
| `02_dataset.ipynb` | Состав данных: баланс классов, сплиты, число записей на атаку, распределение длительностей относительно `t_fixed` | `data/manifests/` + заголовки `.npy` | `viz/dataset_viz.py` |
| `03_training.ipynb` | Кривые обучения: loss и val-EER по эпохам, выбранная эпоха | `experiments/<exp>/metrics.jsonl` | `viz/training.py` |
| `04_results.ipynb` | Результаты: DET/ROC, EER с доверительными интервалами, матрицы ошибок, разбивка EER по атакам | `experiments/<exp>/scores.parquet` + `eval_metrics.json` | `viz/results.py` |

Нумерация задаёт естественный порядок чтения — от «как выглядят данные» к
«какой получился результат», — но ноутбуки независимы: каждый можно запускать
отдельно, лишь бы существовали нужные ему артефакты.

## Запуск

```bash
uv run jupyter lab
```

`jupyterlab`, `ipykernel` и `ipywidgets` лежат в группе `dev` и ставятся по
умолчанию. `jupyterlab` включён намеренно, чтобы развёртывание не предполагало
конкретный редактор; `ipykernel` обслуживает и внешних клиентов вроде VS Code —
это ядро, а не интерфейс.

Голое окружение прогона без ноутбуков: `uv sync --no-dev --extra cpu`.

## Правила

### 1. Restart & Run All — обязательно

Каждый ноутбук должен проходить **Restart & Run All** сверху вниз без ошибок.
Ноутбук, который работает только «если сначала выполнить ячейку 7, потом 3» —
сломанный, даже если картинки в нём красивые.

### 2. Логика — в `src/viz/`, не в ячейке

Типичная ячейка выглядит так:

```python
from src.viz import style, results

style.apply_style()

metrics = results.load_metrics("smoke_lfcc_statpool")
scores  = results.load_scores("smoke_lfcc_statpool")

fig = results.plot_det(scores, metrics)
style.save_figure(fig, "det_curves")
```

Если для графика не хватает функции — она добавляется в `src/viz/`, а не пишется
в ячейке. Так график остаётся воспроизводимым и переиспользуемым.

### 3. Ноутбуки ничего не пересчитывают

EER, доверительные интервалы, матрицы ошибок, разбивки по атакам читаются из
`eval_metrics.json`. Единственное исключение — сами кривые DET/ROC: они строятся
из `scores.parquet`, потому что кривая целиком в JSON не хранится, но точка EER
наносится на них из JSON.

### 4. Экспорт — через `style.save_figure`

Фигуры уходят в `reports/figures/`. Линейные графики (loss, DET, ROC) — в
**вектор** (PDF/SVG), спектрограммы и тепловые карты — **растр** с DPI ≥ 300.

### 5. Запуск из корня проекта

Импорты вида `from src.viz import …` работают, только если рабочая директория —
корень проекта. Запускайте `jupyter lab` оттуда.

## Что в ноутбуках делать не стоит

- **Считать метрики.** Для этого есть Стадия 3 и `src/utils/metrics.py`.
- **Читать аудио своим `librosa.load`.** Используйте `viz.audio.load_waveform` —
  он идёт через тот же декодер и тот же ресемпл, что Стадия 1. Иначе картинка
  незаметно рассогласуется с кэшем.
- **Держать состояние между ноутбуками.** Каждый — самостоятельный, читает с
  диска всё, что ему нужно.
- **Коммитить тяжёлый вывод.** Перед коммитом полезно очистить вывод ячеек:
  ноутбук с гигабайтом встроенных картинок неудобен в git, а фигуры и так лежат
  в `reports/figures/`.
