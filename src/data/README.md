# `src/data/` — данные: от сырого аудио до батча

Всё, что происходит с данными до того, как их увидит модель. Здесь живут
**Стадия 0** (индексация) и **Стадия 1** (признаки), а также код, которым
Стадии 2–3 читают подготовленные данные.

Ключевая идея: **датасет-специфичное знание заканчивается на границе манифеста.**
Ниже манифеста весь код работает с одной канонической таблицей и не знает, из
какого набора пришла строка.

---

## Файлы

| Файл | Роль | Стадия |
|---|---|---|
| `schema.py` | Каноническая схема манифеста + валидатор. Контракт «любой датасет → пайплайн». | 0 |
| `sources/` | Адаптеры конкретных датасетов (см. [`sources/README.md`](sources/README.md)). | 0 |
| `manifest.py` | **Стадия 0**: оркестратор — адаптер → валидатор → атомарная запись `.parquet`. | 0 |
| `features.py` | **Стадия 1**: реестр экстракторов признаков + раннер, пишущий per-file кэш `.npy`. | 1 |
| `subsets.py` | Детерминированные стратифицированные подвыборки: манифест → манифест. | 2–3 |
| `selectors.py` | Селекторы `{dataset_id, split}` → склеенный манифест. Общий кусок Стадий 2 и 3. | 2–3 |
| `dataset.py` | Ленивый torch `Dataset` поверх кэша + коллатор. Читающая сторона контракта признак↔модель. | 2–3 |

## `schema.py` — каноническая схема манифеста

Манифест — единственный универсальный интерфейс между датасетами и пайплайном.
Любой адаптер обязан выдавать ровно эту схему.

**Обязательные колонки:**

| Колонка | Тип | Смысл |
|---|---|---|
| `dataset_id` | str | Происхождение записи, напр. `asvspoof2019_la`. Нужна для безопасной склейки манифестов и как часть глобального ключа. |
| `utt_id` | str | Уникален **внутри** датасета. Пара (`dataset_id`, `utt_id`) уникальна глобально. |
| `path` | str | Путь к аудио относительно `data/raw/<dataset_id>/`. |
| `label` | int | `spoof = 1`, `bonafide = 0`. Единая конвенция для всех адаптеров. |
| `split` | str | Нормализованный: `train` / `dev` / `test`. |

**Опциональные колонки** (NULL при отсутствии): `attack_type`, `speaker_id`,
`sample_rate`, `codec`, `duration`.

**Правило отсутствующих полей.** Только явный NULL (pandas NA), **не** магическая
строка `"unknown"` — нужно отличать «поля нет в датасете» от «поле есть, но
значение неизвестно».

> **Уточнение про `attack_type`.** Правило «пропускать NULL» относится к
> **спуф-строкам** с неизвестной атакой. У подлинных записей `attack_type`
> **всегда** NULL по конвенции, и они обязаны участвовать в разбивке EER по
> атакам как отрицательный класс: EER для атаки `A07` — это «весь bonafide
> датасета против спуфа только этой атаки». Буквальное чтение «пропускать все
> NULL» оставило бы разбивку без отрицательного класса. Число пропущенных
> спуф-строк без атаки пишется в `eval_metrics.json`
> (`n_spoof_without_attack_type`), чтобы пропуск был виден, а не молчалив.

**Публичное API:**

- `coerce_schema(df)` — привести кадр адаптера к каноническому виду (колонки, типы);
- `validate_manifest(df)` — проверить контракт, при нарушении бросить с **полным**
  списком проблем;
- `empty_manifest()` — пустой типизированный кадр как основа для адаптера.

Валидатор — не формальность: он превращает «агностичность» из лозунга в
проверяемое свойство, через которое проходит выход *любого* адаптера.

## `manifest.py` — Стадия 0

Тонкий оркестратор: получает адаптер по `dataset_id`, вызывает
`build_validated()`, атомарно пишет `data/manifests/<dataset_id>.parquet`.
Аудио при этом **не загружается** — только пути и метаданные.

```bash
uv run python -m src.data.manifest asvspoof2019_la
uv run python -m src.data.manifest --list
uv run python -m src.data.manifest --all
```

Программно: `build_manifest(dataset_id, config) -> Path`.

Флаги и особенности прогона — в [корневом README](../../README.md#стадия-0--индексация).

## `features.py` — Стадия 1

Три вещи, ради которых модуль устроен именно так:

1. **Реестр экстракторов.** `@register_extractor` кладёт класс в таблицу по имени;
   выбор идёт по имени из CLI/конфига, без if-цепочек. Новый признак = новый класс
   + декоратор, ничего ниже не трогая.
2. **Контракт формы.** Каждый экстрактор отдаёт `float32`-массив **`[T, C]`**
   (T — кадры по времени, C — каналы). Длина здесь **не** нормализуется:
   паддинг и пулинг — обязанность коллатора и модели, кэш хранит сырое `[T, C]`.
   `C` статически известен из параметров и проверяется на каждом выходе.
3. **Возобновляемость.** Путь выхода детерминирован: (`dataset_id`, `utt_id`)
   + хэш конфига признаков. Файл есть → пропуск. Иначе: загрузка аудио →
   извлечение → атомарная запись.

**Текущие экстракторы:**

| Имя | `C` | Что это |
|---|---|---|
| `lfcc` | 60 | LFCC: 20 коэффициентов × (static, Δ, ΔΔ) |
| `logmel` | 80 | лог-мел-спектрограмма |

**Интерфейс экстрактора** (`FeatureExtractor`): подкласс — это frozen dataclass
со своими гиперпараметрами (они и есть конфиг признаков) плюс атрибуты класса
`name` и `impl` и методы `target_sr`, `channels`, `extract(y, sr)`.
Поля dataclass'а автоматически попадают в `spec()` → в хэш кэша, поэтому менять
их безопасно: другой набор параметров = другой хэш = другая папка кэша, старое
не перезаписывается.

Поле `impl` (источник реализации) тоже входит в хэш: LFCC/MFCC из разных
библиотек дают разные числа при одинаковых параметрах.

**Раскладка кэша:**

```text
data/features/<name>-<hash>/
├── _spec.json                    # параметры признака + версии библиотек
└── <dataset_id>/
    ├── <utt_id>.npy              # [T, C] float32
    └── _failures.csv             # только если были сбои: файл + реальная причина
```

**Про декодирование.** Аудио грузится **ровно один раз в раннере**
(soundfile → моно → ресемпл в `target_sr` экстрактора), поэтому сами экстракторы —
чистая математика над сигналом и легко тестируются. Декодирование идёт напрямую
через `soundfile`, а не `librosa.load`: при сбое видно настоящую ошибку
libsndfile, а не обёртку audioread. При сбое подключается фолбэк на `ffmpeg`.
Публичная `load_audio()` вынесена наружу, чтобы слой визуализации читал аудио
**тем же** декодером, из которого считался кэш — иначе картинка незаметно
рассогласовалась бы с кэшем.

## `subsets.py` — подвыборки

Подвыборка — это **не копия аудио**, а отфильтрованный манифест: он указывает на
те же файлы в `raw/` и те же записи в `features/`. По диску бесплатна.

**Единственный неочевидный инвариант, ради которого модуль написан именно так:**

> сначала **стабильная сортировка** по (`dataset_id`, `utt_id`), и только **потом**
> выборка с зафиксированным seed.

Без сортировки тот же seed на иначе упорядоченном `DataFrame` даёт **другие**
строки — и эксперименты становятся несравнимыми.

**Стратификация:** минимум по (`split`, `label`); желательно по `attack_type`;
при склейке нескольких датасетов раннер Стадии 2 добавляет `dataset_id` в
стратификацию автоматически. Бюджет `n` раскладывается по стратам методом
наибольших остатков, так что сумма квот в точности равна `n`.

**API:** `make_subset(df, n, seed, stratify)`, `subset_filename(...)`,
`save_subset(...)` → `data/manifests/subsets/<ds>__n<N>__seed<S>.parquet`
(самодокументирующее имя). В цикле обучения подвыборка обычно передаётся прямо
в `Dataset`; сохранение на диск — опция.

**Синергия с кэшем.** Признаки подвыборки — строгое подмножество полных. Рабочий
цикл: Стадия 1 на подвыборке (быстро) → итерации Стадий 2–3 → Стадия 1 на полном
манифесте, которая **пропускает** уже посчитанное.

> **Оговорка.** Подвыборка — для итерации и отладки. Итоговый EER берётся на
> полном тесте: на малом тесте оценка EER имеет высокую дисперсию, а порог
> определён плохо.

## `selectors.py` — чтение манифестов по селекторам

Список `{dataset_id, split}` → склеенный `DataFrame`. Общий кусок Стадий 2 и 3:
обе читают одни и те же манифесты по одинаковым правилам. Разница только в
наборе колонок — обучению хватает меток, оценке нужен ещё `attack_type` для
разбивки EER по атакам.

Держать это в одном месте важно по существу, а не из вкуса к DRY: `concat` и
`group-by` — единственные законные употребления `dataset_id` ниже манифеста.
Пока такая функция одна, правило видно и проверяемо; две копии в разных стадиях
начали бы расходиться.

**API:** `load_selectors(paths, selectors, extra_columns)`,
`stratify_for(yaml_stratify, selectors)`.

## `dataset.py` — ленивый Dataset и коллатор

Читающая сторона контракта признак↔модель. Признаки читаются **лениво, по одному
примеру**: в памяти только текущий батч, не датасет. `__init__` держит **только**
метаданные (id и метки как numpy-массивы, не `DataFrame`) — иначе каждый воркер
`DataLoader` продублировал бы их в памяти.

**Фиксация длины.** У примеров разное `T`, поэтому каждый приводится к общей
`t_fixed`:

- длинный — **кроп**: на обучении окно берётся **случайно** (лёгкая аугментация:
  за эпохи модель видит разные фрагменты длинных записей), на валидации и оценке
  — **детерминированно с начала записи**;
- короткий — **повтор-паддинг**, а не нули: так кадры остаются «настоящими».

Смещение случайного окна берётся из torch-ГСЧ, который `DataLoader` сеет по
воркерам и эпохам, поэтому прогон воспроизводим от общего seed, хотя окно
закономерно меняется от эпохи к эпохе.

**Что отдаёт коллатор:** батч `[B, t_fixed, C]` + `lengths` `[B]`. При
повтор-паддинге все кадры валидны, поэтому маска сейчас тривиальна — но
`lengths` возвращается всегда, интерфейс сохранён под будущую честную переменную
длину: включается сменой коллатора, без правки моделей.

**Перенос на устройство здесь не делается** — это обязанность цикла обучения.

**Поведение при неполном кэше.** Примеры без `.npy` отфильтровываются с
предупреждением (`ВНИМАНИЕ: N/M примеров без .npy …`); если не осталось ни одного —
бросается ошибка с подсказкой запустить Стадию 1. Несовпадение `C` у конкретного
файла тоже ловится с явным сообщением.

## Как добавить новый датасет

Никаких правок в этой папке не требуется, кроме самого адаптера — см.
[`sources/README.md`](sources/README.md).

## Как добавить новый признак

1. Новый класс в `features.py`: frozen dataclass, наследник `FeatureExtractor`,
   с атрибутами `name`, `impl` и методами `target_sr`, `channels`, `extract`.
2. Декоратор `@register_extractor` над классом.
3. Всё. Ни `dataset.py`, ни модели, ни стадии обучения/оценки не трогаются:
   новый признак получит свою папку кэша по хэшу и станет доступен в
   `--list` и в YAML-конфигах.
