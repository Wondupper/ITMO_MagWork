# `src/data/sources/` — адаптеры датасетов

Единственное место в проекте, где живёт **датасет-специфичное знание**: где лежит
аудио, откуда брать метки, как называются сплиты, где спрятан файл с протоколом.

Наружу адаптер выдаёт только канонический манифест. Всё, что находится ниже
манифеста, не знает и не должно знать, из какого набора пришла строка — это
прямое следствие правила не-ветвления: `if dataset_id == …` ниже манифеста
считается ошибкой проектирования, чинить надо схему, а не вставлять частный случай.

## Контракт адаптера

Подкласс `DatasetAdapter` обязан задать атрибут `dataset_id` и реализовать
`build()`. Его обязанности:

1. **Найти аудио** в своём `data/raw/<dataset_id>/`.
2. **Разрешить метку** для каждого файла. Источник — дело адаптера: протокол,
   имя папки, шаблон имени.
3. **Разрешить сплит** — родной (прочитанный из датасета и нормализованный в
   `train`/`dev`/`test`) либо явно пометить его отсутствие.
4. **Заполнить опциональные поля** там, где они есть, и поставить **NULL** там,
   где их нет.

Выход обязан пройти валидатор (`schema.validate_manifest`). Метод
`build_validated()` в базовом классе делает это автоматически: `build()` →
`coerce_schema` → `validate_manifest`.

**Реестр.** Декоратор `@register` кладёт класс в таблицу по `dataset_id`;
`get_adapter(dataset_id, config)` достаёт его без if-цепочек, `available()`
возвращает список зарегистрированных.

## Помощники из `common.py`

| Функция / константа | Что делает |
|---|---|
| `label_to_int(s)` | `'spoof'` → 1, `'bonafide'` → 0, иначе ошибка. Единая конвенция меток. |
| `norm_attack(attack, label_int)` | Приводит поле атаки к канону; строки-заглушки (`""`, `"-"`, `"bonafide"`, `"unknown"`, `"none"`, `"n/a"`) → NULL. |
| `norm_vocoder(vocoder, label_int)` | Поле вокодера → строка или NULL. Логика та же, что у атаки: поле определено только у спуфа, заглушки (`bonafide`, `unknown`, `-`) → NULL. |
| `norm_condition(value)` | Поле условия → строка или NULL. Заглушками считаются только `""`, `"-"`, `"n/a"`: `none`/`nocodec` — **содержательные** значения («сжатия не было»), базовая точка разбивки. |
| `codec_from_suffix(path)` | Кодек **контейнера** по расширению файла. |
| `iter_audio(root)` | Обход папки с фильтром по `AUDIO_EXTS`. |
| `read_protocol(path)` | Чтение пробел-разделённого протокола в список полей. |
| `protocol_table(path, fields=…)` | Протокол → `{utt_id: {имя поля: значение}}`. Проверяет ширину строки и уникальность ключа. |
| `AUDIO_EXTS` | `.flac`, `.wav`, `.mp3`, `.m4a`, `.ogg` |

Помощники — про **общее**. Датасет-специфика (какое поле в какой позиции, где
лежит файл ключей) остаётся в самих адаптерах.

### `protocol_table` — почему словарь, а не именованные аргументы

Сигнатура принимает `fields={"utt_id": 1, "speaker_id": 0, "attack": 4, …}`, то
есть отображение «имя поля → индекс в строке». Помощник намеренно **не знает
семантики** полей: он читает файл, проверяет ширину строки и уникальность ключа,
и отдаёт словарь. Благодаря этому новое поле (условие, вокодер) добавляется
правкой одного адаптера — сам помощник не трогается.

Что он ловит, чего не ловил прежний код: **дубль ключа** (молчаливая перезапись
дала бы манифест с недостачей строк без единой ошибки) и **короткую строку** — с
номером строки в сообщении.

## Текущие адаптеры

| `dataset_id` | Роль в проекте | Родной сплит → канон | Откуда метки | `speaker_id` | `attack_type` |
|---|---|---|---|---|---|
| `asvspoof2019_la` | train + dev (есть и eval) | `train`/`dev`/`eval` → `train`/`dev`/`test` | CM-протоколы внутри архива | есть | `A01–A19` |
| `asvspoof2021_la` | test | `eval` → `test` | `raw/LA-keys-full/keys/LA/CM/trial_metadata.txt` | есть | `A07–A19` |
| `asvspoof2021_df` | test (аудио частично) | `eval` → `test` | `raw/DF-keys-full/keys/DF/CM/trial_metadata.txt` | есть (неоднородный) | `A07–A19` + `TaskN-teamXX` |
| `for-2seconds` | test (кросс-датасет) | `training`/`validation`/`testing` → `train`/`dev`/`test` | имя папки (`real`/`fake`) | нет | нет |

`for-2seconds` — намеренно «крайний случай» контракта: у него нет ни протокола,
ни дикторов, ни разметки атак, только имена папок. Если контракт работает и на
нём, и на ASVspoof с полными метаданными, значит он действительно универсален.

## Особенности, о которые легко споткнуться

### ASVspoof 2019 LA

Индексация ведётся **по CM-протоколу** (`ASVspoof2019_LA_cm_protocols/`, по
файлу на сплит), поэтому манифест — это ровно CM-триалы. В папках `flac` у
`dev`/`eval` лежат также ASV-enrollment записи (файлы вида `LA_D_A…`), которых в
CM-протоколе нет; в манифест они **не попадают**.

Сплит определяется парой (протокол ↔ папка аудио), а не префиксом `utt_id`.
Формат CM-строки: `speaker utt - attack label` (третье поле — заглушка `-`).

### ASVspoof 2021 LA и DF

**Файлы с ключами лежат вне папки датасета** — соседями папок аудио в `data/raw/`:

```text
raw/
├── asvspoof2021_la/flac/          # аудио
├── LA-keys-full/keys/LA/CM/       # метки
├── asvspoof2021_df/flac/          # аудио
└── DF-keys-full/keys/DF/CM/       # метки
```

Адаптеры резолвят их через корень `raw/` (константа `_KEYS_RELPATH`). Файл
`*.cm.eval.trl.txt`, лежащий рядом с аудио, — это **только список имён**, меток
в нём нет.

**Формат `trial_metadata.txt`** (пробел-разделитель, метка — поле 6, аудио —
`flac/<utt_id>.flac`):

- **LA, 8 полей:** `speaker(1) utt_id(2) codec(3) transmission(4) attack(5) label(6) trim(7) phase(8)`.
  У bonafide поле атаки = `bonafide`.
- **DF, 13 полей:** `speaker(1) utt_id(2) codec(3) source(4) attack(5) label(6) trim(7) phase(8) vocoder(9)` + VCC-мета (10–13).
  У bonafide поле атаки = **`-`**.

⚠️ Подлинные строки размечены **по-разному** (LA: `bonafide`, DF: `-`) — это
классическая ловушка. Оба варианта нормализуются в `attack_type = NULL`.

**Условия записи попадают в манифест.** Поля тракта разбираются в отдельные
колонки — это то, на чём держится разбивка EER по кодекам:

| Датасет | Поле протокола | Колонка | Наблюдаемые значения |
|---|---|---|---|
| LA | `codec` (3) | `condition` | `none`, `alaw`, `ulaw`, `g722`, `gsm`, `opus`, `pstn` |
| LA | `transmission` (4) | `transmission` | `loc_tx`, `sin_tx`, `ita_tx`, `mad_tx`, `-` → NULL |
| DF | `codec` (3) | `condition` | `nocodec`; `{high,low}_{mp3,m4a,ogg}`; `mp3m4a`, `oggm4a` |
| DF | `vocoder` (9) | `vocoder` | `traditional_vocoder`, `neural_vocoder_autoregressive`, `neural_vocoder_nonautoregressive`, `waveform_concatenation` |

⚠️ Колонка `codec` в манифесте — это **контейнер файла** (везде `flac`), а не
поле 3 протокола. Кодек сигнала лежит в `condition`. Строка `codec=flac,
condition=low_mp3` не противоречива: сигнал прогнали через mp3 и разжали обратно.

У LA поля связаны не свободно: `none` встречается только с `-`, `pstn` — только с
`mad_tx`; остальные пять кодеков — с каждым из трёх каналов. Итого 17 комбинаций,
а не полный декартов набор.

⚠️ **Поле `vocoder` размечено теми же заглушками, что и атака** — у подлинных
строк там литерал `bonafide`, у части спуфа `unknown`. Обрабатывается
`norm_vocoder()` (не `norm_condition()`): оба → NULL. Иначе `unknown` стал бы в
разбивке EER отдельной псевдогруппой, а `bonafide` продублировал бы информацию,
которая и так есть в `label`. Обе категории восстанавливаются: подлинные — это
`label == 0`, спуф без разметки вокодера — `label == 1 & vocoder.isna()`.

**Что по-прежнему дропается:** `source` (DF), `trim`, `phase`
(`progress`/`eval`/`hidden`), VCC-мета (10–13). Колонок под них нет; добавляются
тем же аддитивным способом, если понадобится считать метрики на конкретной фазе.

**DF скачан намеренно частично** (`part00` из трёх). Адаптер индексирует
присутствующее аудио, а метку берёт из **полных** ключей. Следствие: EER по DF
считается на подмножестве — так и указывается в работе. Докачивать не нужно.

### FoR / for-2seconds

Протокола нет вообще: метка выводится из имени папки (`real` → bonafide = 0,
`fake` → spoof = 1), сплит — из верхней папки (`training`/`validation`/`testing`).
Дикторов и атак нет → NULL.

`utt_id` выводится из **относительного пути** (без расширения, `/` → `__`), а не
из имени файла: имена между папками `real/` и `fake/` могут совпадать, поэтому
одного stem не хватило бы для уникальности внутри датасета — а `utt_id` входит в
ключ кэша признаков.

## Как добавить новый датасет

1. Создайте модуль `sources/<my_dataset>.py`.
2. Опишите класс — наследник `DatasetAdapter` с атрибутом `dataset_id`
   (он же — имя папки в `data/raw/`) и методом `build()`, возвращающим
   `DataFrame` канонической схемы.
3. Навесьте `@register`.
4. Добавьте импорт модуля в `sources/__init__.py` — иначе регистрация не
   произойдёт.
5. Положите данные в `data/raw/<dataset_id>/` с нетронутой родной структурой.
6. Проверьте: `uv run python -m src.data.manifest <dataset_id>` — валидатор
   скажет, если схема нарушена, а сводка (число строк, разбивка `split × label`,
   заполненность опциональных полей) сразу покажет, всё ли разобралось.

Ничего за пределами этой папки править не нужно — ни стадии, ни модели, ни
визуализацию.

**Чек-лист при написании адаптера:**

- [ ] `label` — по конвенции `spoof = 1`, `bonafide = 0`, а не «как в датасете»;
- [ ] `split` нормализован в `train`/`dev`/`test`;
- [ ] `utt_id` уникален внутри датасета (осторожно с одинаковыми именами файлов
      в разных подпапках);
- [ ] `path` — относительно `raw/<dataset_id>/`, а не абсолютный;
- [ ] отсутствующие поля — **NULL**, а не `"unknown"`;
- [ ] строки-заглушки в поле атаки прогнаны через `norm_attack`;
- [ ] если у датасета нет родного деления, сплит назначается по явной политике
      (предпочтительно **по диктору**, чтобы записи одного диктора не попали и в
      `train`, и в `test` — это известный источник завышенных метрик; при
      отсутствии `speaker_id` — случайное с seed и **честная оговорка об
      ограничении** в тексте работы).
