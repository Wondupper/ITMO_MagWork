# `src/utils/` — общие утилиты

Небольшие модули, которые используются больше чем одной стадией. Критерий
попадания сюда простой: **если один и тот же кусок логики нужен двум стадиям, он
должен существовать в одном экземпляре.** Не из вкуса к DRY — из-за
сопоставимости чисел: две копии кода, считающие «одно и то же», со временем
разойдутся, и в работе окажутся несравнимые метрики.

---

## Файлы

| Файл | Роль | Кем используется |
|---|---|---|
| `io.py` | Атомарная запись `.parquet` и `.npy`. | Стадии 0, 1, 3 |
| `inference.py` | Инференс-проход «загрузчик → скоры». | Стадии 2 (val) и 3 (test) |
| `metrics.py` | EER, бутстрэп-доверительный интервал, ΔEER двух прогонов, матрица ошибок. | Стадии 2 и 3, `viz/results.py`, `viz/compare.py` |

---

## `io.py` — атомарная запись

```python
atomic_write_parquet(df, path) -> Path
atomic_write_npy(arr, path) -> Path
```

Обе функции пишут во временный файл **в той же папке**, а затем делают
`os.replace(tmp, final)` — операция атомарна в пределах одной файловой системы.

**Почему это критично, а не «аккуратность ради аккуратности».** Возобновляемость
Стадии 1 и Стадии 3 держится на проверке «файл существует → пропустить».
Без атомарной записи падение *посреди* записи оставило бы наполовину записанный
файл, который при следующем запуске был бы засчитан как готовый — и молча испортил
бы результат. То есть атомарность здесь не оптимизация, а **предусловие
корректности** механизма пропуска готового.

Тот же паттерн обслуживает чекпойнты Стадии 2 (`tmp` + `os.replace` + ротация
последних `keep_last`), чтобы не остаться с единственным битым чекпойнтом.

Для `.parquet` нужен движок `pyarrow` — он в обязательных зависимостях.

## `inference.py` — общий инференс-проход

```python
iter_batch_scores(model, loader, device) -> Iterator[(scores, labels)]
predict_scores(model, loader, device)    -> (scores, labels)
```

**Зачем отдельным модулем.** Val-EER Стадии 2 и итоговый EER Стадии 3 должны быть
сопоставимы. Общая формула метрики — только половина дела; вторая половина в том,
чтобы скоры, которые в неё подаются, получались **буквально одним кодом**. Иначе
разойтись могут не формулы, а мелочи прохода: что именно считается скором, в
каком режиме модель, что происходит с последним неполным батчем.

**Скор** = сырой логит модели, больше ⇒ увереннее «спуф». Сигмоида не
применяется: EER инвариантен к монотонному преобразованию, а логит удобнее
хранить.

**Инвариант порядка.** При `shuffle=False` и `drop_last=False` порядок выдачи
загрузчика совпадает с порядком примеров в `Dataset`. На этом Стадия 3 связывает
i-й скор с i-м ключом (`dataset_id`, `utt_id`), **не заводя id внутрь батча**.
Именно поэтому фильтрация тестового манифеста (исключение уже посчитанных ключей
при возобновлении) делается **до** конструктора `Dataset` — тогда выравнивание
сохраняется само.

> Если будете менять инференс-проход, этот инвариант надо держать в голове:
> любой `shuffle=True` или `drop_last=True` на оценке тихо перемешает скоры с
> ключами.

## `metrics.py` — метрики детекции

```python
compute_eer(scores, labels)                     -> EER(eer, threshold)
bootstrap_eer(scores, labels, n_boot=1000, ...) -> EERInterval
paired_bootstrap_eer_delta(scores_a, scores_b, labels, ...) -> EERDelta
confusion_at(scores, labels, threshold)         -> Confusion
```

**EER** (Equal Error Rate) — сквозная метрика проекта: та же функция считает
val-EER по эпохам на Стадии 2 и итоговый EER на Стадии 3. Реализация — через
ROC-интерполяцию точки, где FPR = FNR (`sklearn.metrics.roc_curve`).

**Конвенция:** больше скор ⇒ увереннее «это spoof» (положительный класс = 1).
⚠️ В официальных протоколах ASVspoof CM-скор ориентирован **обратно** — при
сравнении с чужими скор-файлами знак надо инвертировать.

### Бутстрэп-интервал

`bootstrap_eer` даёт перцентильный доверительный интервал, **стратифицированный
по классу**: подлинные и спуф пересэмплируются независимо, с сохранением
исходных количеств.

Почему именно так: EER определяется парой условных распределений скора, а
соотношение классов в тесте — это свойство дизайна теста, а не случайная
величина. Общий ресэмплинг «в кучу» добавил бы к интервалу дисперсию классового
баланса, которой в реальности нет.

**Что интервал НЕ покрывает** (это стоит оговорить в тексте работы): он
описывает разброс *одной обученной модели на данном тесте*, а не разброс метода.
Неопределённость из-за конечности обучающей выборки и случайности самого
обучения сюда не входит.

### Сравнение двух прогонов

`paired_bootstrap_eer_delta` даёт `ΔEER = EER(B) − EER(A)` и перцентильный интервал
у самой разности. Отдельная функция нужна потому, что два интервала по отдельности
на вопрос «стало ли лучше» не отвечают: непересекающиеся интервалы различие
показывают, но **пересекающиеся его не опровергают**.

Бутстрэп **парный**: обе модели оценены на одних и тех же записях, поэтому в каждом
повторе пересэмплируется один набор индексов и по нему считаются оба EER. Общая для
обеих моделей часть разброса (какие записи попали в тест, насколько они трудные) при
вычитании сокращается, и интервал получается уже, чем при двух независимых
бутстрэпах. Стратификация по классу — та же, что в `bootstrap_eer`.

Требование к входу: `scores_a[i]`, `scores_b[i]` и `labels[i]` относятся к одной и
той же записи. Выравнивание по ключу (`dataset_id`, `utt_id`) делает
`viz/compare.align_scores`; здесь проверяются только длины.

**Что интервал НЕ покрывает:** случайность обучения. Это сравнение **двух конкретных
обученных моделей** на данном тесте, а не двух методов вообще — последнее потребовало
бы прогонов с разными seed.

### Матрица ошибок

`confusion_at(scores, labels, threshold)` считает матрицу при **заданном** пороге.
Стадия 3 пишет её в двух рабочих точках, и путать их нельзя:

| Точка | Порог откуда | Как читать |
|---|---|---|
| `at_val_threshold` | выбран на валидации **до** теста | честная точка, оценка обобщения |
| `at_eer_threshold` | подобран на **самом тесте** | иллюстрация распределения ошибок в точке равного риска, **не** оценка обобщения |

Обе пишутся и подписываются в `eval_metrics.json` именно затем, чтобы их нельзя
было перепутать в тексте.

**Зависимости модуля:** только `numpy` и `scikit-learn`.

## Что сюда не относится

- **Датасет-специфичная логика** — в `src/data/sources/`.
- **Построение графиков** — в `src/viz/`; `metrics.py` числа считает, но не рисует.
- **Одноразовые помощники одной стадии** — пусть остаются в самой стадии.
  Модуль переезжает сюда, когда у него появляется **второй** потребитель.
