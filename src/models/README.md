# `src/models/` — реестр архитектур

Здесь лежат модели-классификаторы «подлинная речь / синтез». Папка устроена как
**реестр**: цикл обучения не знает про конкретную сеть — он берёт её из таблицы
по имени из YAML-конфига и работает через узкий контракт. Смена архитектуры =
новый класс + декоратор, ни одной правки в `train.py` или `evaluate.py`.

Это та же схема, что у реестра адаптеров датасетов и реестра экстракторов
признаков.

---

## Файлы

| Файл | Роль |
|---|---|
| `model_base.py` | База `AntispoofModel` + реестр: `@register_model`, `get_model(name, in_channels, **overrides)`, `available_models()`. |
| `statpool.py` | `statpool_mlp` — baseline на statistics pooling. |

---

## Контракт модели

Модель обязана:

- **объявить ожидаемое число каналов входа** `in_channels` (= `C` кэша признаков).
  Стадия 2 сверяет его с признаком **до** обучения, Стадия 3 дополнительно
  сверяет `feature_hash` из чекпойнта. Рассинхрон «учили одним признаком,
  оцениваем другим» ловится до долгой работы, а не проявляется кривой метрикой;

- **реализовать `forward(x, lengths) -> logits`:**

  | Тензор | Форма | Тип | Смысл |
  |---|---|---|---|
  | `x` | `[B, T, C]` | float32 | батч с общей длиной `T` |
  | `lengths` | `[B]` | long | число валидных кадров каждого примера |
  | `logits` | `[B]` | float32 | **один** логит на пример |

- **самостоятельно свернуть ось времени.** Пулинг или свёртка по `T` до
  фиксированной длины — обязанность **модели**, а не кэша: кэш хранит сырое
  `[T, C]`, и контракт остаётся стабильным для любых `T`.

**Про `lengths`.** Параметр присутствует в сигнатуре всегда, даже сейчас, когда
Стадия 2 подаёт примеры единой длины и маска тривиальна. Это сохраняет интерфейс
на будущее: когда понадобится честная переменная длина с маскированием паддинга,
достаточно сменить коллатор — модели править не придётся.

**Конвенция выхода.** Один логит, положительный класс = spoof (1). Функция
потерь — `BCEWithLogitsLoss`; дисбаланс классов корректируется через
`pos_weight = N_neg / N_pos`, считаемый по фактическим train-меткам. Сигмоида к
логиту нигде не применяется: EER инвариантен к монотонному преобразованию, а
логит удобнее хранить (нет насыщения в 0/1).

## `statpool_mlp` — текущий baseline

```text
[B, T, C] → покадровый Linear + ReLU (проекция C → H)
          → масочный mean/std-pooling по T
          → [B, 2H]
          → MLP-голова
          → один логит [B]
```

Гиперпараметры (задаются в YAML через `model.params`): `hidden`, `dropout`.

**Почему именно эта модель первой:**

- **лёгкая и дешёвая на CPU** — согласуется с ракурсом работы «лёгкий метод под
  ограниченные ресурсы» и служит честной точкой отсчёта, от которой измеряется
  улучшение;
- **C-агностична**: первый слой строится под фактический `in_channels`, так что
  LFCC-60, logmel-80 и любой будущий признак работают без правок;
- **time-агностична**: statistics pooling (mean + std по времени) сворачивает
  любую длину `T` в вектор фиксированного размера — ровно как требует контракт.

Пулинг уважает `lengths` (усредняет только по валидным кадрам). При единой длине
Стадии 2 маска тривиальна, но код готов к переменной длине.

> ### ⚠️ Это НАПОЛНЕНИЕ, а не выбор архитектуры
>
> `statpool_mlp` существует, чтобы проект прошёл end-to-end и цикл обучения был
> проверен на чём-то работающем. Это **не** ответ на вопрос «какая архитектура
> нужна методу» — он решается по обзору литературы и экспериментам, а не тем,
> что оказалось написано первым. Менять `statpool_mlp` «на что-нибудь получше»
> прямо сейчас было бы ошибкой: следующая архитектура **добавляется рядом**, а
> baseline остаётся как точка отсчёта.

## Как добавить архитектуру

```python
# src/models/my_net.py
from .model_base import AntispoofModel, register_model


@register_model
class MyNet(AntispoofModel):
    name = "my_net"

    def __init__(self, in_channels: int, hidden: int = 256):
        super().__init__(in_channels=in_channels)
        ...

    def forward(self, x, lengths):
        # x: [B, T, C] -> logits: [B]
        ...
```

1. Новый класс — наследник `AntispoofModel` с именем реестра.
2. `@register_model` над классом.
3. Импорт модуля туда, где собирается реестр (по аналогии с уже
   зарегистрированными моделями), — иначе класс не попадёт в таблицу.
4. В YAML-конфиге: `model.name: my_net`, гиперпараметры — в `model.params`.

Проверить, что модель видна:

```bash
uv run python -m src.train --list
```

**Что при этом НЕ нужно трогать:** `train.py`, `evaluate.py`, `dataset.py`,
экстракторы признаков, слой визуализации. В этом и смысл реестра.

## Что важно помнить про чекпойнты

Чекпойнт самодостаточен: в `meta` пишутся `model_name`, **`model_params`**,
`feature`, `feature_hash`, `in_channels`, `t_fixed`. Стадия 3 восстанавливает
модель **по этим метаданным**, а не по YAML — веса и конфиг могут оказаться от
разных прогонов.

`model_params` лежат там не для красоты: без них `get_model(name, in_channels)`
собрал бы сеть с **дефолтными** размерами, и `load_state_dict` упал бы при любом
отличии от конфига обучения (например `hidden: 256` вместо 128).

Практическое следствие для новых архитектур: **все гиперпараметры, влияющие на
форму весов, должны быть именованными аргументами `__init__`** и приходить из
`model.params`. Значение, зашитое внутрь `forward` или вычисленное из чего-то
внешнего, не попадёт в чекпойнт и сломает восстановление модели.

Если в чекпойнте `model_params` нет (старый формат), Стадия 3 печатает
предупреждение и собирает модель на дефолтах — при несовпадении это честно
падает на `load_state_dict`, а не подставляет молча значения из YAML.
