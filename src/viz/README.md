# `src/viz/` — построение графиков

Вся логика фигур для текста работы. Ноутбуки из [`notebooks/`](../../notebooks/README.md)
только импортируют отсюда, вызывают и сохраняют — сами они ничего не считают и
не рисуют.

**Главное правило этой папки: здесь ничего не пересчитывается.** Числа считают
стадии пайплайна и кладут в артефакты на диск; `viz` их **читает и рисует**.
Иначе в работе могли бы разойтись число в таблице и число на графике — а это
прямо бьёт по измеримости результата.

---

## Файлы

| Файл | Что рисует | Что читает | Ноутбук |
|---|---|---|---|
| `style.py` | — (общий стиль + сохранение) | — | все |
| `audio.py` | осциллограмма, спектрограмма, карта признаков | аудио из `raw/` + `.npy` из кэша | 01 |
| `dataset_viz.py` | баланс классов, состав сплитов, счётчики атак, длительности | манифесты + заголовки `.npy` | 02 |
| `training.py` | кривые обучения | `experiments/<exp>/metrics.jsonl` | 03 |
| `results.py` | DET, ROC, распределение скоров, матрица ошибок, EER по разрезам | `scores.parquet` + `eval_metrics.json` | 04 |
| `compare.py` | сравнение прогонов: EER с усами CI, ΔEER, DET-оверлей, разрезы | те же артефакты нескольких экспериментов | 05 |

Все функции `plot_*` возвращают `matplotlib.Figure` — показать её или сохранить
решает ноутбук.

## `style.py` — единый вид всех фигур

```python
apply_style()                                  # общие rcParams
save_figure(fig, name, paths=None, formats=…)  # экспорт в reports/figures/
```

Одно место, задающее вид всех графиков работы: размеры шрифтов под печать, сетка,
поля. Ноутбуки его только вызывают — так фигуры из разных ноутбуков выглядят как
один документ, а не как четыре разных.

**Правило форматов:** линейные графики (loss, DET, ROC) — в **вектор** (PDF/SVG),
они масштабируются без потери качества; тепловые карты и спектрограммы — **растр**
с DPI ≥ 300. `save_figure` по умолчанию пишет PDF; для растровых сюжетов
передавайте `formats=("png",)`.

## `audio.py` — что вообще видит модель

Графики уровня одной записи. Это не метрика, а иллюстрация: она нужна, чтобы в
работе можно было объяснить, из чего берётся решение, и чтобы самому заметить,
если с признаками что-то не так.

```python
pick_examples(paths, dataset_id, n=1, ...)       # выбрать записи из манифеста
load_waveform(paths, row, extractor)             # аудио тем же декодером, что Стадия 1
load_feature(paths, row, extractor)              # готовый .npy из кэша
describe(row)                                    # человекочитаемая подпись
plot_waveform(...) / plot_spectrogram(...) / plot_feature_map(...)
plot_example(paths, row, extractor, ...)         # тройка «волна + спектрограмма + признаки»
plot_class_pair(paths, dataset_id, extractor, …) # та же тройка для двух классов
```

> **Важно про источник данных.** Аудио читается **тем же декодером**, что и на
> Стадии 1 (`data.features.load_audio`): тот же фолбэк на ffmpeg, тот же ресемпл
> к `extractor.target_sr`. Свой `librosa.load` в ноутбуке дал бы слегка другие
> числа и незаметно рассогласовал бы картинку с кэшем. Признаки не
> пересчитываются вовсе — читается готовый `.npy`.

## `dataset_viz.py` — состав данных

Читает манифесты Стадии 0. Нужен по двум причинам: описать данные честно
(сколько чего, насколько несбалансировано) и увидеть то, что потом объясняет
метрики — перекос классов, разное число записей на атаку, разброс длительностей
относительно `t_fixed`.

```python
load_manifests(paths, dataset_ids)               # склейка манифестов
composition_table(df)                            # сводная таблица состава
plot_class_balance(df) / plot_split_composition(df)
plot_attack_counts(df, dataset_id)
frame_counts(paths, extractor, dataset_id, ...)  # длины в кадрах из кэша
plot_durations(counts, extractor, ...)           # гистограмма с отметкой t_fixed
```

**Про длительности отдельно.** Колонку `duration` адаптеры не заполняют — она
опциональная и по факту NULL у всех четырёх текущих датасетов. Поэтому
длительность берётся из числа кадров кэша признаков: `T · hop / sr`. Это не
обход контракта, а более полезная величина: модель работает именно с кадрами, и
сравнивать с `t_fixed` надо их. Читаются **только заголовки** `.npy` (через
memmap), данные с диска не поднимаются.

Гистограмма длительностей с отметкой `t_fixed` — это тот график, по которому
видно, у каких датасетов записи систематически короче окна и, значит,
повторяются при паддинге.

## `training.py` — кривые обучения

Читает `experiments/<exp>/metrics.jsonl` — по строке на эпоху: `epoch`,
`train_loss`, `val_eer`, `val_threshold`, `lr`.

```python
load_history(experiment, paths=None) -> DataFrame
best_epoch(history) -> int | None
plot_training(history, title=…)
plot_val_threshold(history, ...)
```

Зачем эта картинка в работе: она показывает, что обучение вообще сходилось и что
выбранная эпоха (`best.pt`) не взята с потолка. Заодно на ней видны две типовые
неприятности — расхождение loss и val-EER (переобучение) и «лучшая» эпоха,
выигравшая случайно на шумной валидации.

## `results.py` — результаты Стадии 3

```python
load_scores(experiment, paths=None)   -> DataFrame   # scores.parquet
load_metrics(experiment, paths=None)  -> dict        # eval_metrics.json
eer_table(metrics)                    -> DataFrame   # EER + CI по датасетам
plot_det(scores, metrics=None, ...)
plot_roc(scores, ...)
plot_confusion(metrics, dataset_id, at="eer")        # at: "eer" | "val"
plot_score_hist(scores, metrics, dataset_id, ...)    # распределения скора по классам
available_groups(metrics, dataset_id) -> list[str]   # какие разрезы посчитаны
plot_eer_by_group(metrics, dataset_id, column="attack_type")
```

**Разделение обязанностей.** EER, доверительные интервалы, матрицы ошибок и
разбивка по атакам **читаются из готового JSON**, а не пересчитываются.
Единственное исключение — сами кривые DET/ROC: они строятся из `scores.parquet`,
потому что кривая целиком в JSON не хранится. Это отрисовка той же выгрузки, а
не второй расчёт метрики: **точка EER наносится на кривую из JSON**.

**Почему DET, а не только ROC.** DET-кривая — доменный стандарт в анти-спуфинге,
по ней читается EER. Оси в нормальных отклонениях (probit-шкала, отсюда
зависимость от `scipy`): различия в области малых ошибок не сжимаются в угол
графика.

**Разбивка EER по разрезам** ценится комиссией: агрегированная метрика скрывает,
где метод проседает. `available_groups` возвращает разрезы, реально посчитанные у
датасета (блоки `by_*` в JSON), — ноутбук перебирает их, а не жёсткий список.
Читать разбивку нужно **вместе с числом записей в группе**: оно подписано под
столбцом, а полная картина состава — в ноутбуке 02.

В заголовке графика стоит режим разбивки из JSON: `pooled` (отрицательный класс
общий — у подлинной записи атаки нет) или `matched` (подлинные взяты из той же
группы — так считается разбивка по кодеку, который применён к обоим классам).
Смысл чисел в этих режимах разный, поэтому режим подписан на самой картинке, а не
оставлен в тексте работы.

**Распределение скоров** (`plot_score_hist`) отвечает на вопрос, которого не видно
по EER: EER — свойство порядка скоров, а не их положения. Если матрица на пороге с
валидации выглядит вырожденной при приличном EER, здесь сразу видно почему —
распределения разделены, но сдвинуты относительно порога, выбранного на другом
домене.

**Матрица ошибок рисуется в двух точках** (`at="eer"` и `at="val"`) — см.
пояснение про рабочие точки в [`src/utils/README.md`](../utils/README.md).

## `compare.py` — сравнение прогонов (Стадия 3 × N)

```python
compare_table(experiments, paths=None)               -> DataFrame  # exp × dataset
align_scores(exp_a, exp_b, dataset_id, paths=None)   -> (scores_a, scores_b, labels)
delta_table(exp_a, exp_b, paths=None, n_boot=1000)   -> DataFrame  # ΔEER + CI
plot_eer_compare(experiments, paths=None)                          # столбики с усами CI
plot_det_compare(experiments, dataset_id, paths=None)              # DET-оверлей
plot_group_compare(experiments, dataset_id, column="attack_type")
```

**Зачем отдельный модуль.** `results.py` описывает ОДИН эксперимент и читает его
артефакты; здесь вопрос другой — «стало ли лучше», и он по устройству
межэкспериментный. Разделение модулей повторяет разделение ноутбуков: 04 —
предусловие «есть один прогон», 05 — «есть два и больше».

**Почему ΔEER, а не два EER рядом.** Пересекающиеся доверительные интервалы двух
прогонов **не** означают, что разницы нет. Утверждение работы делается о самой
разности, поэтому интервал строится у неё — парным бутстрэпом по одному и тому же
набору пересэмплированных записей (`utils/metrics.paired_bootstrap_eer_delta`).

**Про правило «здесь ничего не пересчитывается».** Оно не нарушено, но держится
проверкой: `align_scores` сверяет EER, пересчитанный из `scores.parquet`, с числом
из `eval_metrics.json` того же прогона и падает при расхождении. Соединение
выгрузок — по глобальному ключу (`dataset_id`, `utt_id`), а не по порядку строк;
при неполном совпадении тестовых наборов сравнение идёт по пересечению с
предупреждением, иначе разность считалась бы на разных знаменателях.

## Если график не строится

| Симптом | Причина |
|---|---|
| Нет `metrics.jsonl` / пустая история | не прогнана Стадия 2 либо неверное `name` эксперимента |
| Нет `scores.parquet` / `eval_metrics.json` | не прогнана Стадия 3 |
| Пустая карта признаков или ошибка чтения `.npy` | пример отсутствует в кэше (см. `_failures.csv` в папке кэша) |
| Длительности не строятся | не построен кэш признаков для этого датасета — величина берётся из кадров, а не из манифеста |
| Фигура выглядит иначе, чем остальные | забыт вызов `apply_style()` в начале ноутбука |
| `нет разбивки по '<колонка>'` | колонка не размечена у этого датасета — см. `available_groups()` |
| `EER из scores.parquet не совпал с eval_metrics.json` | артефакты от разных прогонов: перезапустите Стадию 3 |
